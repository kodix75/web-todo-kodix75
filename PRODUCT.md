# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

One person — the repo owner — using this as a personal daily task list. They
open it repeatedly through the day, often for a few seconds at a time, and want
to capture a thought before it disappears and see what actually matters next.

## Product Purpose

A personal daily driver for tasks. Success means near-zero-friction capture, an
unmistakable sense of what to do next, and completion that feels worth doing —
so the list gets used every day instead of abandoned.

## Positioning

A single-user, local-first daily cockpit: keyboard-first capture, a small set of
high-signal states (priority, due date, tags, recurrence), and momentum you can
feel. Deliberately not a team project-management tool.

## Operating Context

- Desktop browser is primary; mobile is a real secondary case.
- Used in short bursts: quick add, quick check-off, quick scan.
- Keyboard use is first-class: quick add, command palette, shortcuts.
- Tasks carry due dates, priorities, tags, and recurrence.
- Data is personal and local to the browser.

## Capabilities and Constraints

Confirmed: create, edit, complete, and delete tasks; due dates; priorities;
tags with filtering and search; progress and daily streak; recurring tasks;
keyboard shortcuts and a command palette; persistence in the browser.

Undecided: sync/accounts (not planned for this build), notifications, and
calendar integration.

## Evidence on Hand

No real user data, testimonials, or brand assets exist. Demo tasks must be
authored at full fidelity and labelled synthetic wherever they could be mistaken
for real user content. There is no existing visual identity to preserve.

## Product Principles

1. Capture beats organize: adding a task must never feel like filling a form.
2. Show the next move, not the whole backlog.
3. Every completed task should give a small, honest hit of momentum.
4. The keyboard is the fastest path to everything.
5. Calm by default, loud only when it earns attention.

## Accessibility & Inclusion

Keyboard-complete operation, visible focus, sufficient contrast, reduced-motion
support, and semantic controls are required.
